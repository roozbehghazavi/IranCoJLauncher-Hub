# IranCoJ Launcher Hub

Everything the **IranCoJ Launcher** downloads for *Call of Juarez: Bound in Blood* multiplayer:
maps, mods, and (later) launcher and IranCoJ Edition releases.

## Where things live

| What | Where | Read by |
|---|---|---|
| All maps | Release **[`maps`](../../releases/tag/maps)** (one file per map) | Launcher v3 via `catalog.json` |
| Mod manifests | `mods/<Id>.json` | Launcher v3 via `catalog.json` |
| Mod packages | Release **[`mods`](../../releases/tag/mods)** (one zip per mod version) | Launcher v3 |
| Mod folders | `<ModName>/` with a `version.txt` | Launcher v2.0.1; zipped for v3 by CI |
| `catalog.json` | Generated by CI: every map and mod with size, SHA-256 and URL | Launcher v3 |
| `manifest.json` | Generated by CI: maps in `MapsNet/` with SHA-256 | Launcher v2.0.1 (legacy) |
| `MapsNet/` | Maps kept in git for v2.0.1 (legacy, under 100 MB each) | Launcher v2.0.1 (legacy) |
| `tools/build_hub.py` | Generates the files above | `.github/workflows/hub.yml` |

Never edit `catalog.json` or `manifest.json` by hand. The **Build hub** workflow rewrites them on every push.

## Adding or updating a map

- **Under 100 MB:** put the `.pak` in `MapsNet/`, commit and push. CI uploads it to the `maps` release
  and updates both `catalog.json` and `manifest.json`, so v2.0.1 and v3 players both get it.
- **100 MB or more:** open the [`maps` release](../../releases/tag/maps), choose *Edit*, drag the `.pak`
  in, and save. Then run **Actions → Build hub → Run workflow** so `catalog.json` picks it up.
  Only launcher v3 can download these.

To remove a map: delete it from `MapsNet/` (if it is there) **and** delete its file from the `maps` release.

## Adding or updating a mod

Every mod has a manifest, `mods/<Id>.json`. The launcher installs and uninstalls mods from it with one
button, the same way on Windows and Linux, and keeps a backup of every game file a mod replaces.

```json
{
  "id": "NewClasses",
  "name": "New Classes",
  "description": "Shown in the launcher.",
  "version": "1.0.3",
  "package": "IranCoJ_NewClasses_1.0.3.zip",
  "exclude": ["README_INSTALL.txt", "mods.txt"],
  "loadDll": ["newclasses.dll"],
  "shared": ["dinput8.dll"],
  "disable": ["CoJ2/Data/common_mp_meshes.rpack"]
}
```

| Field | Meaning |
|---|---|
| `id` | Same as the file name. Never change it once players have the mod. |
| `folder` **or** `package` | `folder`: a folder in this repo; CI zips it and uploads it to the [`mods` release](../../releases/tag/mods), version from its `version.txt`. `package`: a zip you upload to the `mods` release yourself; then `version` is required. |
| `exclude` | Files in the zip that are not copied (readmes, `mods.txt`). |
| `loadDll` | Lines the launcher adds to `mods.txt` (and removes on uninstall). |
| `shared` | Files several mods ship (e.g. `dinput8.dll`): kept until the last mod using them is uninstalled. |
| `disable` | Game files renamed to `.disabled` while the mod is installed. |
| `windows` / `linux` | Optional per-platform overrides of any field above. |

All paths are relative to the game folder, with forward slashes.

**Folder mod:** change the files, bump `version.txt`, push. **Package mod:** upload the new zip to the `mods`
release, update `package` and `version` in its manifest, push. Then check that the **Build hub** run is green.

## Moving off launcher v2.0.1

Launcher v2.0.1 reads `MapsNet/`, `manifest.json` and the top-level mod folders directly, so they stay
as they are for now. Once most players are on v3:

1. Delete `MapsNet/` and `manifest.json`. All maps are already in the `maps` release.
2. Move the mod folders into `mods/` and give each a `mod.json` (install type, e.g. copy or installer).
3. Launcher and IranCoJ Edition builds are published as releases here (`launcher-v*`, `edition-v*`).
