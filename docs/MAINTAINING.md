# Maintaining the hub

Everything the **IranCoJ Launcher** downloads for *Call of Juarez: Bound in Blood* multiplayer:
maps, mods, and (later) launcher and IranCoJ Edition releases.

## Where things live

| What | Where | Read by |
|---|---|---|
| All maps | Release **[`maps`](../../../releases/tag/maps)** (one file per map; the only copy) | The launcher via `catalog.json` |
| Mod manifests | `mods/<Id>.json` | The launcher via `catalog.json` |
| Mod folders | `mods/<Id>/` with a `version.txt` | Zipped by CI into the `mods` release |
| Mod packages | Release **[`mods`](../../../releases/tag/mods)** (one zip per mod version) | The launcher |
| `catalog.json` | Generated by CI: every map and mod with size, SHA-256 and URL | The launcher |
| `tools/build_hub.py` | Generates the files above | `.github/workflows/hub.yml` |

Never edit `catalog.json` by hand. The **Build hub** workflow rewrites it on every push.

Launcher v2.0.1 is retired (November 2026): its files (`manifest.json`, the maps in `MapsNet/`, the mod folders at
the top level) are gone; players need launcher v3.

## Adding or updating a map

1. Clean the pak: `python tools/clean_map_paks.py <map>.pak` (a map may only carry `Data/MapsNet/...` and a
   map-named `.scr` at its root).
2. Open the [`maps` release](../../../releases/tag/maps), choose *Edit*, drag the `.pak` in (same name to update
   a map), and save.
3. Run **Actions → Build hub → Run workflow**. CI downloads every new or changed map, checks it, and adds it to
   `catalog.json`; a map that ships files it must not fails the run (clean it and upload it again).

To remove a map: delete its file from the `maps` release, then run the workflow.

## Adding or updating a mod

Every mod has a manifest, `mods/<Id>.json`. The launcher installs and uninstalls mods from it with one
button, the same way on Windows and Linux, and keeps a backup of every game file a mod replaces.

```json
{
  "id": "NewClasses",
  "name": "New Classes",
  "description": "Shown in the launcher.",
  "version": "1.0.3",
  "package": "IranCoJ_NewClasses_1.0.3.zip",
  "exclude": ["README_INSTALL.txt", "mods.txt"],
  "loadDll": ["newclasses.dll"],
  "shared": ["dinput8.dll"],
  "disable": ["CoJ2/Data/common_mp_meshes.rpack"]
}
```

| Field | Meaning |
|---|---|
| `id` | Same as the file name. Never change it once players have the mod. |
| `folder` **or** `package` | `folder`: `mods/<Id>`, a folder in this repo; CI zips it and uploads it to the [`mods` release](../../../releases/tag/mods), version from its `version.txt`. `package`: a zip you upload to the `mods` release yourself; then `version` is required. |
| `exclude` | Files in the zip that are not copied (readmes, `mods.txt`). |
| `loadDll` | Lines the launcher adds to `mods.txt` (and removes on uninstall). |
| `shared` | Files several mods ship (e.g. `dinput8.dll`): kept until the last mod using them is uninstalled. |
| `disable` | Game files renamed to `.disabled` while the mod is installed. |
| `optional` | `true`: installed only when the player chooses it. Without it the mod is core: launcher alpha.7+ installs it into every Edition automatically. Installed mods of either kind are kept up to date. |
| `windows` / `linux` | Optional per-platform overrides of any field above. |

All paths are relative to the game folder, with forward slashes.

**Folder mod:** change the files, bump `version.txt`, push. **Package mod:** upload the new zip to the `mods`
release, update `package` and `version` in its manifest, push. Then check that the **Build hub** run is green.
